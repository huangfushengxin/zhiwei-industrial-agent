## 二、作品简介（**≤50 字**）

```
基于 Agnes Harness 的工业设备运维智能体：自主诊断、模拟维修，用数据验证修没修好。
```

## 三、作品详情

```
【要解决的问题】
工业旋转设备（泵、风机、电机）运维长期依赖经验：异常发现晚、故障判断靠个人经验、
修完没有客观验收。常见做法是"报警→人工排查→经验判断→换件"，早期劣化容易漏掉，
维修效果也无法量化验证。

【方案与实现】
智维用 Agnes Harness 作为智能体运行底座、Agnes 模型作为唯一模型，
把工业设备运维做成可执行、可验证的六步闭环：
  ① 数据读取 → ② 异常检测 → ③ 故障诊断 → ④ 维修方案 → ⑤ 模拟维修 → ⑥ 维修后验证
验证未通过时自动重新规划并再次维修（最多 3 次）。
整套工业能力以 9 个 MCP 工具的形式接入 AGH，Agent 通过自然语言自主编排调用。

【技术亮点】
1) 异常检测：基线比对 + 局部滚动中位数 + 鲁棒 z 分数（中位数/MAD），
   用滚动中位数吸收周期性工况波动，正常工况零误报；
2) 故障诊断：把各测点的持续偏移方向与相对强度构成特征向量，
   与故障知识库做余弦相似度匹配，输出候选故障、置信度与判据；
3) 维修方案：知识库驱动，给出停机策略、预计工时、安全措施（含 LOTO）、
   分步工序（每步含工具与验收标准）、备件清单；
4) 模拟维修：按"修复彻底度 effectiveness"生成维修后复测数据，
   残留偏移 =(1-effectiveness)×可解释偏移，因此"修不彻底"会被真实检出；
5) 跨基线验证：维修后数据一律以【维修前健康基线】为参照，
   避免"从第一秒就存在的残留故障"被当成正常而漏判；
6) 异常处理：验证不通过时不假装修好，而是给出残留测点、残留幅度与残留故障候选，
   触发重新规划 → 再次维修 → 再次验证。

【可验证性】
提供 4 个自动化验收脚本，一键复现：
诊断准确率 5/5、闭环 6/6、异常恢复 4/4、三测试案例 3/3，MCP 工具 9/9 可调用。
每个阶段都留存 AGH 会话导出与闭环 trace 作为运行证据。

【创新性与发展价值】
把"维修效果"从主观判断变成可量化的数据结论（健康度、残留 σ、改善率），
并让 Agent 具备"发现自己诊断错了并纠正"的能力（错误诊断→验证失败→重新规划→修好）。
方案与具体设备解耦：替换数据与故障知识库即可迁移到风机、电机、机床主轴等设备。
```

| 数据 | 团队程序化生成的工业传感器时序数据（温度/振动/转速/电流/压力/流量，1 Hz，每场景 600 点）；含 5 类工况 + 3 份测试文件（正常 / 轴承异常 / 维修失败） |

| 仿真环境 | 自研机理化仿真：设备工况与故障机理建模（`generate_sensor_data.py`）+ 维修效果仿真（`simulate_repair.py`），支持可调修复彻底度 |
| API / 接口 | ① Agnes 模型 API（经 AGH）② MCP（stdio）——本项目自研工具以标准 MCP 协议暴露给 AGH ③ 本地 HTTP + SSE——演示页与执行过程实时通信 |
